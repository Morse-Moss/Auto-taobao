## 三、根因分析

### 根因 1（本轮新发现、也是唯一造成补跑仍失败的）：把「平台导出 0 行」当成「文件损坏」

**证据链**：网林家居推广 ZIP（`商品报表_20261021_181653.zip`，596 B）解包后，CSV 内容为
`表头(78 列) + 一个空行`，文件以 `\n\n` 结尾。Python `csv.reader` 会为这行产出一个
**空数组 `[]`**，其 `len() == 0 ≠ 78`，于是 `promotion-core.mjs:27`
`validatePromotionReport()` 判定「第2行列数与表头不一致」并抛错。

**这是误判**：该店 2026-10-20 确实没有推广数据（这 4 个 SKU 当日未投放），平台导出的是
「有表头、无数据行」的空报表 —— 这是**合法的零数据形态**，不是文件损坏。
同一个错误还连带把 3 店批量导入整批打掉（`推广 3 家（sales1）批量导入失败`），
使本来正常的盖文淘宝、里可林天猫也被推迟到逐店导入才写入。

**判定**：`FAILED / UNCLASSIFIED` → 实际应为 `COMPLETED_WITH_EMPTY`，即「已核对确认无数据」。
链当前没有「零行」这个合法终态，只有「有数据/报错」两态。

**本条属已知缺陷同族**：平台「空态 ≠ 0」的口径在 PATCHES 里已记录过（日报链询单恒缺网林家居），
但商品推广导入器没有对应的空态处理。

### 根因 2：询单判据「入口可见」后只读一次链接，不等待

**证据链**：网林家居首轮 `{"shop":"网林定制家居","hasInquiry":true,"date":"2026-10-20",
"daySelected":true,"link":""}` —— 身份对、日期对、日按钮对，唯独 `link` 为空。
`collect-inquiry-report.mjs:78` 是**一行读完就判死**，没有重试。

**判据为什么必然偶发**：`link` 取自 React fiber 的 `memoizedProps.link`，它是导出接口 URL，
要等报表数据请求返回后才会被填进 props。脚本在「入口出现」后只 `delay(2000)` 就一次性读取，
而入口 DOM 出现 ≠ 数据请求完成。这是在读一个**异步填充的字段**却用**同步判据**。

**补跑佐证**：19 分钟后同一家店、同一条命令，`link` 就有值了、8 行写入成功 —— 说明不是配置/账号问题，
是竞态。盖文淘宝首轮同样症状（`hasParent=false`，连入口都没渲染），补跑时 8 行一次成功。

### 根因 3：推广下载按钮定位是「全表线性扫描 + 单次 elementFromPoint 命中」

**证据链**：里可林天猫首轮失败现场里，**报表已经渲染出 35 行商品数据、URL 日期正确、
无遮挡层**，却报「商品报表任务下载入口不可见」。同一份现场又报
`Runtime.evaluate` 超时 500（30 秒量级的全文档扫描在 35 行表格上会跑很久，容易撞 CDP 超时）。
补跑同店一次成功。

**判据问题**：`collect-product-report.mjs:73` 用
`[...a.querySelectorAll('*')].find(x => x.children.length===0 && innerText==='下载' && rect.width>0)`。
这只接受**叶子节点文字恰好等于「下载」**。阿里妈妈这类 antd/React 组件里，按钮文字常包在
`<span>` 内、或带图标/空格，一旦平台改了 DOM 层级，`children.length===0` 就不成立，
或在扫描期间节点被 React 重渲染替换掉 —— 两种都会落到 `point = null`。
而 `children.length===0` 这个约束在整个文件里重复了 7 次，是同一个脆弱前提。

### 根因 4（非缺陷，但值得记录）：`stoppedAt` 为「一段失败则该店后段全不跑」

盖文淘宝询单失败 ⇒ `stoppedAt=inquiry-collect` ⇒ 推广段直接不执行；
网林家居同理。这是**设计行为**（底单/询单是推广的前置），但它把「1 个缺口」放大成「2 个缺口」，
在告警文案里看起来像两家店各有两处问题。实际只有 3 个独立故障根因。

## 四、今日为什么是这三家（而不是别的店）

三家全部是**单点偶发**，不是系统性故障：

  平台当天那几秒慢了一点就踩中。

## 五、建议修法（未改代码，等拍板）

1. `validatePromotionReport()`：表头校验通过后，若所有数据行都是 `length===0` 的空行 ⇒
   视为**合法零数据**，返回 `{ rows: 0, empty: true }`；导入器据此写「0 行、已核对为空」收据，
   收据 status 用新值 `COMMITTED_EMPTY`，不计入缺口。守卫用例：喂真实空 CSV，断言不抛。
2. `collect-inquiry-report.mjs`：把 `link` 从「读一次」改成「有界轮询」（如 20s / 每 1s），
   与同文件里入口轮询用同一套超时；失败现场补记 `linkPollReads`。
3. `collect-product-report.mjs`：把 `children.length===0 && innerText==='下载'` 放宽成
   「先按 closest('button') 找，再退到 innerText.includes('下载') 且 rect 在视口内」，
   并把全文档扫描收窄到操作行容器内（`a.querySelectorAll`），避免 30s 级扫描撞 CDP 超时。
4. 告警文案：`stoppedAt` 连带产生的缺口，在文案里标「因前一段失败未执行」，
   避免把 1 个故障读成 2 个。

以上第 1 条是**唯一会让网林家居今天就闭合**的改动；2、3 是降低偶发率。
