# 窗口标签页与页签清理（2026-09-18 深夜）

这一轮做完的三件事：
1. 给四台店的窗口挂上**店名标签页**（窗口标题 = 运营叫法，四台互不相同）；
2. 清掉各窗口里的**空白页**（4 个），并查清 `edge://nurturing/` 是**关不掉的**；
3. 让窗口报告能一眼说出**哪一家还停在登录页**（用户原话「也没有登录」）。

## 关于内存数字，务必按这个口径读

| 时刻 | 五实例合计 | 当时窗口里有什么 |
| --- | --- | --- |
| 2026-09-18 傍晚 | 8,326 MB | 含大量重复千牛页与空白页 |
| 本轮清理**前** | 6,297 MB（见 01） | 已无重复千牛；每台 1 个空白页、无标签页（19032/19033 除外） |
| 清理**后** | 6,726 MB（见 08） | 四台各多了 1 个标签页；19031/19034 各多一个关不掉的 `edge://nurturing/` |

**不要**拿 6,297 → 6,726 得出「清理让内存变差」：这一步里**同时新建了 4 个标签页**，
而一个真实页面（renderer 进程）是 200~300MB 量级，空白页几乎不占。

结论（实测）：**清页签省不了内存。** 它真正的价值是消除判据干扰
（重复页签会让「这个后台恰好一个」的判据失败 ⇒ 整家店停在第一步）与消除人眼困惑。
内存的旋钮是「同时开几个实例」，不是「每个窗口开几个页签」。

## 关于「一个开关管两件事」这个自己踩的坑

本轮执行 `--prune --commit` 时，`--commit` 是全局开关 ⇒ 它**顺带把标签页也挂了**，
我原计划「先清 → 量内存 → 再挂」的中间那次对照里混进了 2 个新建标签页，收益数字作废。
已修：`--prune` 现在是**独占意图**（要两件一起做必须显式写 `--label --prune --commit`），
有一条判据专门守着它（测试标题：`--prune 是独占意图`），突变 M1 验证它真的会红。

## 关于「页面读的参数名」（第三个同类缺口）

HTML 里一直有渲染登录状态行的代码，但原判据只断言了 `document.title = shop` 与 `id="shop"` ——
**把状态行那一段整段删掉，测试照样全绿**，而「需要登录」在页面上永远不会出现
（症状是「照着做也看不到提示」，没有任何报错）。
补的判据是跨模块的：从 HTML 里抽出所有 `.get('…')` 的键，与 `labelPageUrlFor` 会写上去的键**双向比对** ——
任一边改名都会红。突变 M13（把 `state` 改名）与 M14（状态行改成无条件显示）**改的都是 HTML 本身**，两条都被抓住。

突变共 **14/14** 被捕获，`runtime/shop-window-label.mjs` 与 `runtime/shop-window-label.html`
还原后 sha256 均逐字节一致（报告见 `03-mutation-report-round2.txt`）。

> 这条形态在本项目已经出现三次：主脚本没传店名、没交真登记表、页面参数名对不上。
> 共同点是**判据只测了一半** —— 测了生产者、没测消费者；测了函数、没测接线。

## 关于 `edge://nurturing/`

新建标签页时 Edge 会顺带打开它，而 `/close` 对它返回 `{"success":true}` 却**关不掉**
（回读同一个 targetId 仍在，见 49 号探针的结论）。
所以它已从关闭计划里移除，改为在报告里标注「关不掉，忽略即可」——
原来的写法每轮都会报「关掉 1 个」而事实没变，那是假动作。
同时给 `pruneTabsOn` 加了**关完回读**的校验：不信 HTTP 200，回读仍在的一律进 `failed`。
