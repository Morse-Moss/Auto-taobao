# 会员名上窗口（2026-09-18 深夜）

## 起因（用户原话，逐字）

> 「没有科塔啊，五个店铺哪里有科塔」

他贴的截图里是运营同事给他的四组账号：

| 会员名（他手里的） | 对应窗口（屏幕上写的） |
|---|---|
| `里可林家居:阿彦` | 里可林淘宝 |
| `网林家居旗舰店:阿彦` | 网林天猫 |
| `随心品质定制:阿彦` | 盖文淘宝 |
| `j873522735:阿彦` | 科塔淘宝 |

## 根因：两套名字都对，对不上的是「人」

`科塔淘宝` 不是编的 —— 它是登记表的键、是飞书「各店铺数据日报」的「店铺」列选项名、
也是运营的「店铺底单」里的原文（`RAW_MAPPING_ROWS` 第 1 行：`科塔全卫定制 / 科塔淘宝`）。

问题在于：**科塔的阿里妈妈会员名是一串数字 `j873522735`，字面上完全没有「科塔」二字**，
而窗口标题写的是运营叫法。人一到机器前，手里只有会员名，屏幕上只有运营叫法，两边没有交集。

同一家店在四个地方本来就有四个名字（见 `shop-identities.mjs` 头部注释），这不是数据错误。
所以修法不是「改名字」，而是**把会员名也写到窗口上**。

## 改了什么

- `runtime/shop-window-label.mjs`
  - 新增 `memberNameFor(shop)` —— 从登记表读会员名。**登记表是数组**（每行 `{ key, ... }`），
    形状不对时抛错，不回落成 `null`。
  - `labelPageUrlFor({ ... member })` 新增 `member` 参数；`ensureLabelTabOn` 透传；
    `parseCli` 支持 `--member`；只读报告也带 `memberName`（「哪一组账号是哪一家」是随时会问的问题）。
- `runtime/shop-window-label.html`
  - 新增一行「会员名 X」（量到才显示，与登录状态同一口径）。
  - 底部提示改为**随登录态分叉**：只有量到「需要登录」时才说「登录页就在本标签页右边那一个里」；
    否则给条件句。原先那句是无条件的 —— 已登录的窗口里根本没有登录页，照着找会找不到。
- 全程**不放密码**（硬纪律：这个 URL 会进浏览历史），并有判据守着。

## 我自己在这轮栽的那一跤（值得单独记）

第一版 `memberNameFor` 写成了**对象下标**：

```js
const row = identities?.[name];   // ✗ 登记表是数组 ⇒ 永远 undefined
```

后果：`memberNameFor` 永远返回 `null` ⇒ 页面上「会员名」那一行永远空着，
**而且没有任何报错** —— 症状与「这家店确实没登记」一模一样。

抓它的是同一轮刚写的判据（`会员名从登记表读…`）。这是本项目「接线没接上」的第 4 个实例，
而这次埋在改动者自己手里。修法是让**形状错误抛错**、只有「找不到这家店」才返回 `null`：
这两种情况的后果完全不同，不能混成一个 `null`。

## 验证

| 项目 | 结果 |
|---|---|
| `node --test runtime/shop-window-label.test.mjs` | **34 / 34**（新增 5 条：会员名 3 条 + 参数名双向比对升级 + 底部提示分叉） |
| 突变验证（`D:/Retire/probe-live/41-mutate-window-label-2.mjs`） | **24 / 24 被抓**（本轮新增 10 条，M15 即上面那一跤的原样复现） |
| 两个被改文件还原后 sha256 | `js` `4a94af8db1eb`、`html` `982a2b282d54` ⇒ **逐字节一致** |

新增判据里最该看的三条：

1. `会员名必须真的落到页面元素上，且是「量到才显示」` —— 会员名不许写死在 HTML 里（那会把某一家店的账号贴到四台窗口上）。
2. `标签页 URL 里只许出现账号名，绝不许出现密码` —— 键集合是封闭的（`shop/port/member/state/ok`），
   且页面不许读任何密码类参数、不许有密码输入框。
3. `底部提示必须随登录态变` —— 防「对已登录的窗口指一个不存在的登录页」。
