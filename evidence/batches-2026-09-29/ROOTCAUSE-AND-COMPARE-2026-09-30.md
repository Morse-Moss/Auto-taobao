## 四、与运营无关、属脚本侧真缺陷的两处

1. **盖文天猫 @ sycm-date**：报错 `sycm tab 询单到付款: still outside viewport after scrollIntoView; rect=[452,0,80,22] viewport=1528x732`。
   判据是 `r.left>=0 && r.top>=0 && r.right<=innerWidth && r.bottom<=innerHeight`；而报错里的 rect 用 `Math.round` 打印，
   `top = -0.4` 会被打印成 `0` ⇒ **信息自相矛盾，把真因抹掉了**。真实原因是元素停在视口上沿外 0.4px 就被判失败。
   修法：判据留 1px 容差，或 `scrollIntoView({block:'center'})`；报错改为打印未取整的 rect。
2. **科塔淘宝 @ promotion-submit**：`台账记着 2026-09-29 已提交 营销场景报表_20260930_164204，但它已不在下载任务列表里（列表现有 0 条）`。
   台账 `runtime/promotion-task-ledger.json` 的 key 是**店铺名**（`科塔全卫定制`），而阿里妈妈「下载任务管理」是**账号维度**的列表。
   今天把科塔淘宝的操作员从 `j873522735:嘉慧` 换成 `j873522735:小瓜` ⇒ 新子账号的列表是空的，台账里那笔是旧子账号下的 ⇒ 核不清、fail-closed。
   **（18:5x 现场确认）** 19044 的阿里妈妈页导航到
   `one.alimama.com/index.html#!/report/download-list`，账号 `j873522735:小瓜 ID：412070158` 名下显示
   **「暂无下载任务 / 共 0 项数据」** ⇒ 现场坐实。
   修法：台账 key 加上"账号/会员名"这一维，或换账号时按 SOP 先清这一店铺当天的台账记录。
3. **一条「死的」自证（顺带发现）**：`collect-shop-report.mjs:21` 的 `KNOWN_REPORT_ID = '4300764'`，
   注释说「报表定义 id 变了就说明取的不是同一份报表」，但 `:139` 只比 **CLI 参数**（而该参数的默认值就是 `KNOWN_REPORT_ID` 本身）
   ⇒ **正常跑永远不会响**。而线上预览 URL 里的 `reportId=4306105`（网林天猫）与它不同 ⇒
   这道本该拦住「取错报表」的守卫**事实上是死的**，待确认它与 SOP §3 的口径。
4. **`SYCM_SPACE_URL` 本来就带 `?activeKey=common`**（`collect-shop-report.mjs:23-24`，该文件 mtime 09-26、与 HEAD 一致）
   ⇒ 第三节里「裸 `my_space` 落到解读报告」**只适用于自己写探针时**，不是脚本的问题。
