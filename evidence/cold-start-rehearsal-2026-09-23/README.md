## 一、结论（六条）

1. **停五家店是干净的**：`stop-all.mjs` 报 5/5「已停 proxy / 已停 browser / 停后盘点到:missing」，

2. **起五家店也是干净的**：`start-all-hold.mjs` 之后 7/7 就位（五家店 + 竞品链 + 商家浏览器）。
3. **「归位自己补页」从纯函数结论升级成真机事实**：四家店都是
   `归位：已归位（生意参谋工作页=0 阿里妈妈报表页=0 → 1 1）`，动作全是 `create`，
   之后 5/5 `体检通过：阻断 0 项`。上一批 §二 推的那条路，这次是真的走了。
4. **冷启动不丢登录态**：冷启动之后五家店仍然 5/5 在登录态
   （`判定=ALREADY_LOGGED_IN`，生意参谋与阿里妈妈**两个站点**都 `loggedIn=true`，退出码 0）。
   ⇒ 「每轮关再续跑」不会把登录态弄坏；掉登录是另一条独立的暴露路径（见上一批 §四）。
5. **两条意外**（都已处置，细节见 §五）：
   - 上一批记的那个「本项目孤儿 PID 64332」**不属于本项目** —— 它是 Edge **默认 profile**
     的 crashpad-handler 树，主窗口标题「使用记录 - Apizh」。按「不碰别的进程」的纪律**没动**。
   - 收敛 holder **会带走实例**（与预期相反）：停掉 4 个 holder 之后，竞品链 9222 与商家浏览器
     19022 **整套都没了**。已后台重跑 `start-all-hold.mjs` 恢复（7/7 就位），并补跑了归位把
     商家浏览器的期望页面建回来。
6. **「关再续跑」的阻断项没有变**：仍然是「体检不看登录态」。本批次只证明「关 → 起」这一步
   不丢数据、不丢登录态、不挡整轮；**登录态体检那条能力本批次没造**（它已获授权，是下一件事）。

## 五、两条意外

### 5.1 「孤儿 PID 64332」不属于本项目（纠正上一批的记述）

上一批 §七 把它写成「不属于任何实例的孤儿：msedge 主进程 PID 64332 自身 233 MB + 7 个子进程
= 446 MB」。本批查明：它是 **Edge 默认 profile**
（`C:\Users\Administrator\AppData\Local\Microsoft\Edge\User Data`）的 crashpad-handler 树，
主窗口标题是「使用记录 - Apizh」（见 `tmp/rehearsal-0923/14-windows-after.txt`），
**与我们这七个实例无关**。

⇒ 它**不该由我们清**（它上面还挂着别人的窗口），本批**没有动它**。上一批那句「零风险、立刻见效」
对它不成立；要清得由用户自己处置。

### 5.2 收敛 holder 会带走实例（与预期相反）

停掉的 4 个 holder 是 PID 8040 / 14536 / 21352 / 55720（`08-holders-collapse.txt`）。
停完回读，**竞品链 9222 与商家浏览器 19022 整套消失**（`09-…-down.txt`）。

根因（从 PPID 看）：这两个实例的**记录者进程**（`start-project-browser.mjs` PID 54708、
`start-daily-report-browser.mjs` PID 63240）的 PPID **都是 34128** —— 那是 09-22 17:49
那批 holder 启动时那次 `start-all` 的父 shell。也就是说这些实例的父链挂在**旧 holder 那一批**上，
停 holder 相当于把它们的父链接拆了。

⇒ 结论（写进纪律）：**「用 taskkill 停 holder 就能顺手带走实例」这个假设是错的；
而「停 holder 只影响 holder 自己」也是错的。** 收敛 holder 必须在实例都起齐之后单独做，
且做完立刻回读对账。本批已恢复（`10`、`11`）。

另外一件必须交代的事：**PID 8040 这个 holder 不是我们这个会话起的**。它的 PPID 是 39696，
命令行是 `D:/Retire/probe-live/start-daily-chain.mjs` —— 那是**另一个会话/另一条工作流**
（`D:/Retire/probe-live/`，不属本仓库）托着的。证据：同一天早上 08:14–08:28 有一次完整的
`evidence/daily-job-2026-09-22/` 跑完（`chain 退出码=0`，5 家店全 ok），10:11–10:12 又有一批
由别的工具新起的 node。

⇒ 纪律：**这台机器上别的会话在并发跑同一个仓库的链**，停进程前必须先确认「谁在跑」；
而仓库里的定时任务**今天 11:40 还会自己跑一次**（它会调幂等的 `start-all`）。
