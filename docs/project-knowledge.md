# 生意参谋自动化项目知识

## 项目定位

面向电商运营与市场分析工作的受控浏览器自动化项目。系统复用用户已登录的 Edge 会话，将生意参谋搜索排行、小旺神竞品分析、灰豚小红书话题热度、文件校验和飞书多维表导入拆成多个可复用 Skill，并为每一步设置明确的数据合同、安全停止条件和验收证据。

本文只记录当前已验证能力、历史证据和对外表述边界；多租户平台的目标架构、分层职责和迁移原则以 [`docs/architecture/README.md`](architecture/README.md) 为准。本文中的流程图描述现有实现，不代表目标架构已经落地。

项目不是绕过平台风控的爬虫，也不承诺无人值守长期运行。遇到登录、验证码、账号风险、权限或安全提示时必须停止并交给用户处理。

- 从飞书公式产生的完整 `A候选` 队列读取关键词，从灰豚官网切换到红薯版“话题搜索”逐词查询。

- `1000w`（`10,000,000`）只作为**灰豚浏览量**参与 A 条件的门槛；**灰豚只读 `内容热度`，不产出它，也不把浏览量折算成内容热度**（灰豚技能的写入白名单里只有 `灰豚话题浏览量` 一个字段，写 `内容热度` 会被判未授权）。
- `内容热度` 的**原本规则**（2026-08-09 字段合同第 17 行）：性质 = **AI 预测**（不是采集）；输入 = 原始关键词 / 关键词分类 / 细分标签 / 用户意图；做法 = **只预测内容创作潜力**；硬约束 = 输出必须带 `AI预测-` 前缀、**不冒充真实平台热度**。提示词 F 原话：「这里没有内容平台的真实热度数据，只能预测内容创作潜力」「不得把该结果描述为小红书、抖音、知乎或其他内容平台的真实热度」。⇒ 它与 `灰豚话题浏览量`（真实小红书话题浏览量）是 `优先级` 公式里**两个并列独立的输入**：`A条件 = 灰豚话题浏览量 >= 10000000 且 搜索热度∈{中,高} 且 内容热度∈{中,高} 且 交易热度=高`；而 `A候选`（灰豚的输入队列）= 前三个条件已满足但 `灰豚话题浏览量` 仍空 ⇒ **顺序是「内容热度」在前、「灰豚」在后**。

## 工程设计

```text
已登录 Edge 会话
  -> 共享 CDP Proxy
  -> 页面目标重新发现
  -> 受控采集状态机
  -> 临时 CSV/XLSX
  -> 数据与文件双重校验
  -> 原子发布
  -> 授权飞书副本导入
  -> 行数与结构验收
  -> 同 Base 周表结构复制
  -> 永久编号复用与历史批次追加
  -> LOCAL_INPUT_READY 人工检查点
  -> 飞书 A候选队列
  -> 灰豚红薯版同名话题采集
  -> 灰豚浏览量回填与公式验收
  -> 历史重点达标快照与当前两周计数同步
```

- 浏览器控制：共享 `web-access` Proxy，所有动作前重新发现 target，导航后不复用旧 target id。
- 安全边界：不读取密码、Cookie、Token、浏览器存储或认证头；不加入 stealth、指纹伪装或反检测逻辑。
- 数据可靠性：页面展示值是事实源；插件文件名与页面结果冲突时保留原文件并记录告警。
- 失败处理：登录/验证/风控进入 `HUMAN_REQUIRED`；无进度进入 `STALLED`；校验失败的文件不得进入飞书。
- 可测试性：浏览器流程、CLI、参数准备、输出发布、文件校验、字段检查和粘贴合同均有离线回归测试。2026-08-16 两周批次认定修正后，公式、灰豚、周更、历史、清单续跑和字段合同的受影响回归为 `92/92`；受控批次提升另通过真实 Base apply、编号集合校验、幂等 dry-run 和公式结果分布检查。
