# 页面判据失效：复盘与规则（2026-10-29 立）

适用范围：任何「用 DOM 判断页面状态」的代码 —— 采集、导入、登录预检、可见性/就绪判定。
本文不是某次故障的经过记录（那些在 `evidence/` 与 `CHANGELOG.md` 里），而是**规则**：
下次写这类判据时按它写；下次判据失效时按它定位。

## 1. 这次坏在哪（三句话）

1. 掩膜 `DIV#wrapper_dlg_1351`（全屏、z=99999）的子树是空的，弹窗内容写在它的**兄弟节点**里；
   旧判据只遍历「最高 z 层」的子树 ⇒ 读到 `0/0` ⇒ 判成「没有可安全点击的关闭控件」。
2. 屏幕上有「取消」，代码说没有可点的东西。**判据没错，范围错了。**
3. 盖文淘宝是同一族但更隐蔽：点「下载报表」后那枚「确定」被另一个弹窗吃掉，
   流程点到的是**弹窗的**确定，于是 `confirmed=true` 误判成功，错误拖到下游
   「轮询 30s 无新任务」才以「提交任务无法唯一确认」的面目暴露。

## 2. 三条可检查的规则（不是「下次注意」）

### 规则 A：判据只认几何与命中，不认 DOM 父子关系

平台只承诺「你看到的东西在屏幕上」，**不承诺**它在哪棵子树里。一旦判据依赖
「弹窗的一切都在最高层那棵子树内」，平台一次改版就让判据静默失效 —— 不报错，只返回 0。

- 该认的：`getBoundingClientRect()` 的面积/坐标比例、`document.elementFromPoint()` 的命中结果、
  `getComputedStyle` 的 position/z-index/display/opacity。
- 不该认的：`class` 名（平台改版就换）、「内容一定在某容器里」、`children.length === 0` 当可点性判据。
- 本条的反面教材与正面对照都在同一个文件里：`collect-core.mjs` 判「是不是全屏层」
  早就按面积比例算（注释写着「平台发版改类名不会影响这条判据」），
  而同一函数的**候选**却又假设了子树关系 —— 同一份代码里两套哲学。

### 规则 B：`0` 不是结论，是「换一个口径再数一次」的信号

`candidateTotal === 0` 有两种含义：(a) 真的没有可点的东西；(b) 我的扫描范围错了。
旧代码无法区分，于是把 (b) 报成 (a)，人只能靠截图去推翻它。

- 写法：主口径收不到时，**换一个更宽的口径再数一遍**，并把两个数都写进日志与错误文案。
- 现在 `overlayScanExpression()` 输出 `inLayerCandidates`（层内）与 `candidateTotal`（兜底后），
  日志是「层内可点小控件 0 个 ⇒ 改按整页找，整页符合关闭语义的候选 1 个」。
  下一眼就能看出是口径问题还是真没有。
- 兜底必须**带约束**（语义白名单 + 尺寸上限 + 命中测试），否则等于把判据换成「点整页」。

### 规则 C：失败要落在「动作级」，不能落到「流程级」

「提交任务无法唯一确认」是流程级结论（下游轮询说的），真因是动作级（上游点击落错地方）。
归因错，修的方向就错：会去调重试次数、调轮询时长，而真正该查的是遮挡。

- 写法：**关键动作之前**先做一次前置检查，错了当场报，不拖到下游。
  已落地：`submit()` 点「下载报表」之前先查遮挡，关不掉就带 `OVERLAY_NOT_DISMISSED` 报错。
- 判据：一条报错如果读不出「在哪一步、看到什么」，它就不算合格报错。

## 3. 同一机制多份实现：靠计数守卫，不靠记性

这次真正的放大器不是判据，是**接线不一致**：

| 脚本 | 注入 ESC | 取件段查遮挡 | 提交段查遮挡 |
| --- | --- | --- | --- |
| `sycm-alimama-daily-report/collect-promotion-report.mjs` | 有 | 有 | **补上**（只在点「下载报表」之前清一次；关不掉不抛） |
| `sycm-alimama-daily-report/collect-shop-report.mjs` | 有 | 有 | — |
| `sycm-alimama-daily-report/repair-shop-stage.mjs` | 有 | 有 | — |
| `sycm-promotion-data/collect-product-report.mjs` | **补上** | 有 | **补上** |
| `sycm-product-data/collect-product-report.mjs` | 无 | 无 | 无（商品段一直全绿，挂起） |

ESC 是最安全的一招（不用点页面上任何东西，没有点错的可能），而商品链这两个脚本
一直在日志里写「没有注入 pressEscape ⇒ 跳过 ESC 这一步」—— 它自己把缺口打印出来了，
只是没人把它当缺口读。

护栏：`download-entry-wiring.test.mjs` 断言 `pressEscape:` **恰好出现 1 次**，
且守卫必须在点击之前（锚点用 `const clicked=await`，不用「下载报表」四个字 ——
守卫自己的注释里也有这四个字，第一版就是这么假绿的）。

## 4. 存量扫描结果（本次口径）

机制谓词一：「以某个容器的子树作为可交互控件的全集」。
命中 1 处：`collect-core.mjs` 的候选收集 —— **已修**（改为层内优先 + 文档级兜底）。
其余 `document.querySelectorAll`（任务表行、下载入口、iframe 穿透）本来就是文档级，不适用。

机制谓词二：「`length === 0` 直接下结论，没有再数一次」。
扫出的点（关键词候选、文件列表、表格行）语义不同：它们的 0 就是 0，
且都在轮询循环或有明确 reason 里，不适用。挂起一条：推广取件段
`collect-promotion-report.mjs` 的「这一类任务 0 条」仍只报一个口径，
但它同时输出 `finalVerdict.reason`，暂不动（改动它要碰日报主链）。

## 5. 还欠什么（不许当成已修）

1. **真机未验弹窗在场那一刻**。已验的是：真实布局引擎里造出「掩膜 + 兄弟节点 + 取消/立即体验」，
   新判据 `blocked=true`、层内 0、兜底拿到 `BUTTON:取消`、「立即体验」被排除
   （`tmp/probe-new-scan-live.mjs`）。这是真实 DOM 但不是真实弹窗。
   真机判据 = 2026-10-30 10:00 那一轮，若当天平台又弹且三家没卡，才算验过。
2. 商品底单采集（`sycm-product-data`）完全没有遮挡处置。它采的页面至今没出过弹窗（10-28 商品 13/13 全成），
   **无现场 ⇒ 不动**。等它真出一次再修，届时复用同一个 `createOverlayDismisser`，不另写一套。
3. 日报链提交段（2026-10-29 已补一道，但**不是**完整方案）：现在在点「下载报表」**之前**先扫一次全屏层，
   有就关（ESC → 有序候选 → 回读），**关不掉也不抛**（它只做减法，判据仍在后面的复核与列表差集上）。
   刻意没做两件事，理由都是「做了会伤到主链路」：
   - **点完之后不再动手**。那一刻页面上的全屏层很可能就是刚弹出来的下载弹窗本身，而候选表里
     「取消」是合法候选 —— 点下去等于亲手取消自己刚提交的下载。所以提交后的现场只做**诊断**：
     「确定」等不到时，报错里附一句 `全屏层：…`，把「是没弹窗 / 弹窗被挡 / 平台没渲染」分开。
   - **「确定」归属未区分**。现在挑的是「文案=确定且中心点命中自己」的第一个；如果页面上同时
     有两个可点的「确定」（别的营销弹窗 + 下载弹窗），仍可能点错。日报链至今零次发生（7/7 全绿），
     真出一次时的形态是「`提交结果核不清` + 列表无新增」，届时再按「点哪个」单独立项，
     不要在没现场时猜一个判据进来。

## 6. 复发时怎么快速定位（30 秒判据）

1. 先看报错里有没有 `层内可点小控件 0 个 ⇒ 改按整页找` 这句：
   - 有，且整页候选也是 0 ⇒ 点击真被吃掉（掩膜透传/pointer-events），要人看；
   - 有，且整页候选有值但仍失败 ⇒ 选点语义没覆盖这种文案，补白名单，别加大重试。
2. 报错是「提交任务无法唯一确认」这类下游结论时，先去平台的任务列表看**当天有没有那条任务**：
   有 = 下载段被挡；没有 = 提交段被挡。这两条分支的修法完全不同。
3. 别先加大重试次数。这次 5 次重试全落在同一个死循环里：刷新 → 弹窗重弹 → 还是 0/0。
   重试只对「间歇性」有效，对「口径错」无效。
