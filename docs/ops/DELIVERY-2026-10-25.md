## 4. 统一验收口径

任何链都不能只凭以下任一项判成功：宿主 `success=true`、脚本打印“完成”、单条完成提醒、汇总文件或进程退出码。

每条链至少同时满足：

1. 运行回执为完成态，目标业务日正确，参与采集店铺无缺漏。
2. 源数据、写入收据和目标表独立回读一致；没有重复写入、错日写入或静默缺口。
3. 需要人工处理的事项已经明确列出；平台空态按实际留空，不填 0、不编造数据。
4. 证据目录和飞书告警能解释本轮结果。失败时先保留证据，不反复提交同一报表任务。

## 6. 已知限制与对客户的使用边界

1. 运行依赖当前机器的 Edge 用户目录、有效登录态、CDP Proxy、Node 环境和仓库外飞书凭据；这些不是仓库内安装资产，不能仅复制代码就换机运行。
2. 登录失效、验证码、扫码、权限和平台风控需要人工处理；系统不保存或集中代管账号密码，不绕过安全验证。
3. 平台页面或报表结构变化可能需要更新适配判据，不承诺所有平台改版都能自愈。
4. 08:00 早于阿里妈妈数据静止点，低值核对是日常必要步骤。
5. 推广和商品导出 0 行时按实际留空；空数据不是错误，也不得写成 0。
6. 本期只验收销售1部 8 家，不代表销售2部 5 家已启用。
7. 1.12.19/1.12.20 当前是离线验证通过、真机待首跑；未把定向测试表述为全仓或全量端到端测试通过。

## 7. 日常运维与故障处置

日常查看顺序：飞书完成/失败提醒 → 对应证据目录的运行回执 → 目标表独立回读。不要只看调度器的 success 字段。

发生故障时：

1. 记录业务日、店铺、流程、失败阶段、版本号和证据目录；不要先清理现场。
2. 不重复提交同参数报表，不删除飞书生产数据，不强制关闭仍保留故障现场的浏览器。
3. 登录、验证码、风控和权限问题转人工；页面未渲染、列表未读到和真实空列表必须分开判断。
4. 修复遵循 `REPAIR-PROTOCOL.md`：同族清单、修复后三问、攻击包、验证状态四项齐全；修复后必须独立回读。
5. 请求技术支持时提供运行报告和必要截图即可，不发送账号密码、Cookie 或凭据文件。

运维入口：

- 调度与静止点：`docs/ops/DAILY-FLOW-SCHEDULE.md`
