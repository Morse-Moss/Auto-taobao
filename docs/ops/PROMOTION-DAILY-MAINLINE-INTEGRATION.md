# 推广日报主线集成记录

## 当前边界

本流程以主线日报基础设施为唯一基线。当前只提供手工提交、取件、校验和导入准备，不接定时任务，不改变现有普通日报阶段。

## 复用主线能力

- 阿里妈妈身份、浏览器端口和店铺 profile。
- `promotion-task-ledger.mjs` 的任务差集与恢复语义。
- 下载任务管理的生成等待、入口回读、遮罩处理、命中检查和文件系统落盘判定。
- workflow lock、evidence、receipt、失败分类和 Feishu 凭据读取。
- `FeishuClient` 的字段读取、批量写入和回读。

支线的简化提交/取件实现不能替代上述主线能力；接入编排时必须把关键词、人群仅作为新的报表类型接入主线采集器。

## 推广日报独有能力

- 关键词报表页面：30 天累计、昨日、分天、关键词明细维度全选。
- 人群报表页面：30 天累计、昨日、主题/时间/计划维度。
- `keyword`、`audience` 两类任务和各自 CSV schema。
- 推广日报目标表和包含店铺、报表类型的幂等键。

## 配置门槛

`runtime/feishu-targets.mjs` 已增加 `promotionDailyTargets(profile)` 入口，但正式 Base、关键词表、人群表和字段合同尚未登记。未登记时真实导入会 fail-closed，不会回落到普通日报或商品数据目标。

在运营确认 Base、table ID、店铺 profile、字段和唯一键后，才可登记配置并执行单店 dry-run；真实写入需要另行授权。

## 验收顺序

1. 纯函数和配置测试通过。
2. 盖文对应 profile 的关键词、人群任务各提交一次。
3. 下载任务管理取回两个 ZIP，验证文件 hash、CSV 表头、日期、场景 ID 和行数。
4. 与人工 ZIP 逐字段比对。
5. dry-run 生成导入计划。
6. 授权后真实写入并回读。
7. 同一输入重跑，确认零重复。
8. 连续稳定后再接定时和多店铺批量。
