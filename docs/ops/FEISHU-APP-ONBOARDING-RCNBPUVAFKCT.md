# 「各店铺日报」自动写入通道开通清单（给对方组织管理员）

日期：2026-10-16
目的：我们这边的日报自动化系统需要每天自动写入你们组织的多维表格「各店铺日报」（RqzrbD4zIalzjxsSGcbcUPTpnKc）。跨组织的系统应用无法直接加为协作者，所以需要你们组织自己建一个应用作为写入通道。全程约 15 分钟，不涉及任何数据修改。

## 前置条件

1. 一个有开发者后台使用权限的账号（通常是管理员，或管理员在管理后台给某成员开通了「开发者」角色）。
2. 能打开这张「各店铺日报」多维表格，并知道它的所有者是谁（分享面板里名字带「所有者」标记的那个账号）。

## 操作步骤

### 第一步：创建企业自建应用

1. 用上述账号打开 open.feishu.cn（飞书开放平台），右上角确认登录的组织是你们自己的组织。
2. 点「创建应用」，选「企业自建应用」。
3. 应用名称随意，建议「日报写入助手」，便于辨认。
4. 进到应用详情页，记下「凭证与基础信息」里的 App ID（后面要发给我们）。

### 第二步：开通机器人能力（必做）

官方要求：应用以自身身份（tenant_access_token）读写别人的文档，必须先开启机器人能力。

1. 应用管理页 →「添加应用能力」→ 找到「机器人」卡片 → 点添加。

### 第三步：申请接口权限（关键，权限少了搜不到也写不了）

在应用后台「权限管理」里申请以下权限（两个都要）：

1. 「查看、评论、编辑和管理多维表格」（权限名 bitable:app）——写入底单、询单表的必需权限。
2. 「查看、评论、编辑和管理云空间中所有文件」（权限名 drive:drive，或界面上的云文档类读写权限）——列举表格、读取字段结构用。

注意：权限审核方式选「自动开通」可以省事；如果你们组织开了审批流，找管理员批一下即可。

### 第四步：创建版本并发布

1. 应用后台 →「版本管理与发布」→ 创建版本 → 可用范围里添加这张「各店铺日报」表格的所有者账号（可多加几个人，加多了没坏处）。
2. 发布版本，等待管理员审批通过（自建应用一般即时生效）。

两个官方硬规则（不满足的话第五步会搜不到这个应用）：

- 发布版本的可用范围必须包含这张表格的所有者。
- 应用必须至少开通一个云文档 API 权限（第三步已解决）。

### 第五步：把应用加为表格的文档应用协作者

1. 打开那张「各店铺日报」多维表格。
2. 右上角「…」→「更多」→「添加文档应用」。
3. 搜索刚建的应用名，添加，权限选「可编辑」。
4. 特别注意：如果这张表开过「高级权限」，要给应用「可管理」级别；没开过高级权限就选「可编辑」。

这一步不会给任何人发通知，不用等确认消息，加完列表里能看到应用名就成功了。

### 第六步：把凭证发给我们

1. 应用后台 →「凭证与基础信息」。
2. 把 App ID 和 App Secret 发给我们（Secret 只在首次生成时完整显示一次，注意保存）。
3. 安全说明：这套凭据只用于写这张多维表格；如果怀疑泄露，随时可以在后台停用应用，立即失效。

## 我们拿到凭证之后的动作（不用你们做）

1. 我们在系统里配置好凭据（存放于我们机器的本地凭据文件，不进代码仓库）。
2. 跑一次幂等验证（把某个字段写成它当前的值，数据零变更）。
3. 验证通过后，第二天开始每天自动写入 8 家店铺的日报数据，并向你们反馈核对结果。

## 常见问题

问：为什么不能直接邀请你们现有的机器人？
答：飞书的「添加文档应用」只能搜到本组织的应用，跨组织的应用搜不到，这是产品机制，不是操作问题。

问：运营那边需要收到什么通知吗？
答：不需要。全程只有开发者后台和表格分享面板里的操作，不会给任何成员发消息。

问：这个应用会读取或影响我们其他文档吗？
答：不会。我们只对这一张表格调用接口；应用权限范围虽然开了云文档类，但实际调用只会指向这张表的地址。
