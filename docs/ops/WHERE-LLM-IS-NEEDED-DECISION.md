# 哪些部分真正需要接 LLM：按「稳定性 → 性价比」排序的决策

日期：2026-09-16
约束（用户给定，按此排序）：① 结果与稳定性优先，先能稳定跑通；② 一个月还在返工，不能再返；③ 能不用 agent 就不烧 token；④ 能单 agent 就不多 agent。

方法：把过去一个月真实卡点逐条过一遍，只问一个问题——**这个环节的产出能不能由确定性规则算出来？**
能算出来的，就不需要 LLM。判据只认代码，不认「哪个环节听起来更 AI」。

---

## 0. 结论（三条，其中第一条是自我更正）

1. **当前没有任何一个部分「必须」接 LLM。** 包括我上一轮判定为「唯一真正需要 LLM」的四个属性列——它们也已经有确定性实现（见 §2）。逐条对账见 §1。
2. **一个月返工的真因不是缺 LLM，是两件事：建好了没接 + 判据只到执行态。** 前者让功能不生效，后者让「跑完了但结果是坏的」永远不可见。这两件都不烧 token。
3. **LLM 在本项目里唯一的合法位置是「词表兜底」（P3，可选，且排最后）**，而不是主路径。按你给的约束，正确动作是：先不接 LLM，把 P0/P1/P2 做完。

## 2. 唯一曾被认为是 LLM 候选的地方，也已经建好了

我上一轮的判断是：四个属性列「没有确定性规则，只能来自 AI 或人工」，因此是唯一需要 LLM 的位置。
**这条判断是错的，代码里有确定性实现。**

`skills/xws-to-feishu-base/scripts/competitor-v2-core.mjs` 里已存在封闭词表与五个分类器：

| 位置 | 内容 |
| --- | --- |
| `:30-37` | `MATERIALS` / `SHAPES` / `INSTALLATIONS` / `FUNCTIONS` / `STYLES` 五个封闭词表 |
| `:314 matchLabels(title, labels)` | 通用词表匹配 |
| `:352 classifyMaterials` | 含 `HUMAN_MADE_STONE_ALIASES` 别名归一（PMMA/高分子/绮美石/可丽耐/杜邦石/亚克力人造石 → 人造石），取标题中最早出现者 |
| `:367 classifyShapes` | `matchLabels` + 「长方形 → 方形」补规则 |
| `:373 classifyInstallations` | 独立式/嵌入式/内嵌式/靠墙式/台上式/搁置式 归一 |
| `:382 classifyFunctions` | 普通/按摩（冲浪、水疗、气泡按摩、空气按摩）/智能/恒温 |
| `:392 classifyStyles` | 极简（简约）/奶油/日式/轻奢 |

而且 **`:1079 buildCompetitorRecord(row, { searchKeyword })` 是导出函数，把这 8 个字段连同「竞品分类」一次算完**：

- `:1096-1104` 有证据则用词表值，无证据则「无注明」，非有效竞品则「不适用」；
- `:1107-1115` 直接用与飞书公式**同一套阈值**算分级：`月收货人数>=80 且 月收货金额>=200000 → A`；`含人造石 且 >=10 → B`；`价格>=8000 → C`；`价格<1000 → D`。

⇒ 所以属性列与评级链路**都已经有确定性实现，且是导出可用的**。缺的仍然只是「接到周表」。
（`COMPETITOR-FIELD-REFERENCE.md` §8.2 写「其余四个属性仍无路径」，指的是**写入路径**，不是算法不存在。这两件事此前被混为一谈。）

## 3. LLM 真正剩下的位置：词表兜底（可选，排最后）

即使规则齐全，总会有一部分标题因为不含任何词表词而落到「无注明」。这里才是 LLM 的位置，而且形态必须收得很紧：

```
输入：商品标题（+ 卖点）          输出：封闭词表里的值，或「无注明」
批量：复用已存在的批处理面（20 条/次）
失败：回落到「无注明」，不报错、不写脏值
范围：只处理规则未命中的行
```

为什么排最后而不是排第一：

- **它不解决稳定性问题。** 一个月返工是「没接 + 没判据」造成的，不是「无注明的比例略高」造成的。先修前者。
- **成本与收益不对称。** 只有当「无注明比例」实测下来明显偏高、且影响评级时才值得花钱。这需要先用 P0 跑出数字，而不是先假设。
- **它是唯一不可复现的一环。** 其余全部可回归测试；引入它要接受「同样的输入，不同时间可能不同结果」，所以它必须是最小的一块，且必须可整体移除。

**前置条件**：不先拿到「规则命中率 / 无注明比例」的实测数字，就不该讨论要不要上 LLM。

### 3.1 前置条件已满足：实测数字（2026-09-15，本周表 1417 行）

详见 `P0-ATTRIBUTE-WRITEBACK-DIAGNOSIS.md`。要点：

| 字段 | 规则命中 | 词表外表达 | 真无信息 | 现状 → 词表回归上限 |
| --- | --- | --- | --- | --- |
| 材质分类 | 1120 | 40 | 234 | 80.3% → 83.2% |
| 安装方式 | 1028 | 22 | 344 | 73.7% → 75.3% |
| 外形 | 388 | 163 | 843 | 27.8% → 39.5% |
| 功能 | 391 | 116 | 887 | 28.0% → 36.4% |
| 风格 | 320 | 69 | 1005 | 23.0% → 27.9% |

**读法**：右边两列是重点。**60%~72% 的「无注明」是标题里真的没写这个维度**（浴缸标题很少写风格与功能），任何方法都变不出来，LLM 读同一个标题也看不到。「词表外表达」只占 3%~12%，用**词表回归**（把线上高频未命中词补进词表）就能吃掉大部分，成本远低于 LLM，且可审计、可离线回归。

**因此 P3 的定位调整为：它首先是一串「词表回归」任务，而不是一个 LLM 任务。** 按上表，外形能从 27.8% 提到 39.5%——这部分用词表即可，不必上模型。只有当词表回归也追不上、且该维度确实影响评级时，才轮到 LLM。

**另需注意口径**：基准周 08-23 的「真值」与推导**同源**（同一套词表与算法生成，见 §2），因此一致率 93.3%~99.7% 证明的是**可复现性**，不是**正确性**。本项目里真正意义上的人工金标准并不存在。

## 4. 优先级（严格按稳定性 → 性价比）

| 序 | 做什么 | 烧 token | 解决什么 | 依赖 |
| --- | --- | --- | --- | --- |
| **P0** | 把 `buildCompetitorRecord` 接到周表属性列（补上那个不存在的写入方） | 无 | 属性列空 → B 级为 0 / 数据状态「部分待补」 | 无 |
| **P1** | 语义判据四条（`SUSPECT_COVERAGE` / `SUSPECT_FIELD_EMPTY` / `SUSPECT_SCHEMA_DRIFT` / `SUSPECT_IDENTITY`） | 无 | 「跑完了但结果是坏的」可见 | 无 |
| **P2** | 通知改事件驱动 + 告警先落本地收据 | 无 | 卡点发生时飞书会响 | P1 |
| **P3**（可选） | 属性列 LLM 兜底 | 少量 | 压低「无注明」比例 | P0 的实测数字 |
| **P4**（可不做） | 单 agent 分诊，只在失败签名不在已知列表里时 | 少量 | 兜底未知形态 | P1、P2 |

P0 与 P1 零 token、零外部依赖、可立刻开工，而且它们**就是「稳定跑通流程」本身**。
P3 是唯一花得值的 AI 支出，但它需要 P0 先给出数字。P4 可以不做。

---

## 5. 明确不做（按你的约束）

- **不引入多 agent。** 本项目有效并发上限是 1（`fanout.mjs:9`「并发是显式决定：默认并发 1」），多 agent 不增吞吐，只增状态竞争与互相矛盾的判断。
- **不把 `agent-proposal` / `agent-review` 双角色上生产。** 它建好了、有 40 例测试，但它的价值场景是「模型可能乱写」——而 §1 的对账显示，本项目现有卡点里没有一条属于那个场景。留作资产，不接。
- **不把分诊接进采集监督环**（我上一轮的提议，按你的约束撤回优先级）：它花 token、引入不可复现判断，而同类问题用 P1 的零成本判据即可解决。
- **不为了「看起来 AI-native」增加模型调用点。** 判据是 AI-native 的必要条件（系统得先能自己发现问题），模型不是。

## 6. 什么算完成（验收）

P0：
1. 报出周表属性列的**有值率**具体数字（本周表 `tbllWI45sK0DfHpr`）；
2. 与 08-23 周表（唯一有真值）逐字段比对，**一致率**有数字；不一致前 20 条可列出；
3. `待补数据项` 非空行数、`数据状态＝部分待补` 行数均下降且可报；
4. 写入前后有回读校验；不一致时报错而不是静默写。

P1：四条判据各自能用一段已知的坏数据**触发一次**（不是只写代码不验）。

P3（若做）：
1. 先报出规则未命中的**具体比例**，据此估算 token；
2. 命中率提升幅度有数字；
3. 模型失败 / 输出不在词表内时回落到「无注明」，不报错、不写脏值。
