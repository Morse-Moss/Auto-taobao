# WorkBuddy 交接词：商品数据自动采集

请在 `D:\Retire\sycm-automation` 项目目录执行每日商品数据自动采集。不要注册或调用 Windows 任务计划程序；由 WorkBuddy 自己按每日计划触发下面这一条命令：

```powershell
node scripts/run-product-data-job.mjs --date yesterday --commit
```

执行要求：

1. 覆盖五家店铺：里可林淘宝、网林天猫、盖文淘宝、盖文天猫、科塔淘宝。
2. 五家店铺并行采集三类数据：商品底单、商品询单、商品推广。
3. 开始前启动对应店铺浏览器，调用日报流程已有的自动登录守卫；登录失败、验证码、风控或身份不一致时停止后续采集，保留飞书告警和登录收据。
4. 商品底单和商品询单按日期、店铺、商品身份做幂等导入；推广数据按报表行身份去重。不要删除历史数据，不要把底单缺失当成阻止新商品上传的理由。
5. 阿里妈妈推广下载若遇到任务未刷新、操作区隐藏或遮挡层，按程序内置的刷新、重新发现 target、真实鼠标点击和最多三次重试处理；以 ZIP 实际落盘为成功判据。
6. 无论成功还是失败，都执行浏览器释放并进行两次端口回读。释放失败必须在最终报告中标为失败。
7. 运行证据写入：`evidence/product-data-job-YYYY-MM-DD/`。重点读取 `job.log`、`login-preflight.json`、`collection.json`、各店导入 receipt、`promotion-import/receipt.json` 和 `release.json`。
8. 运行结束后汇报：目标日期、五家店各阶段状态、商品/询单/推广源行数与新增行数、重复行数、飞书回读结果、释放端口结果和失败原因。

成功标准：三类数据均完成采集与导入，重复数据没有新增，飞书写入有 receipt，浏览器和代理端口全部释放。

失败标准：任一店登录未通过、采集文件缺失、导入失败、推广 ZIP 未落盘或释放端口仍监听。失败时不要继续假报全流程成功；保留证据并指出具体店铺和阶段。
