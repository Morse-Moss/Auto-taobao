# 生产就绪度评估（2026-09-15）

本文件回答一个具体问题：**这套系统整体架构完成了吗？可以投入企业生产了吗？**

它不新增架构决策，只把仓库里已有的证据（[`PHASE-ARCHIVE.md`](PHASE-ARCHIVE.md) §9/§12、[`README.md`](README.md) §2/§10/§11、
[`docs/standards/README.md`](../standards/README.md) §8、`.github/workflows/ci.yml`）按「生产准入」的口径重新组织，
便于同事做对抗性审查。任何一条结论都可以回到原始出处复核。

## 0. 结论

**架构设计层面：基本完成。** 分层、契约、状态轴与证据链已成文，并经过逐项实测对账（§12）：
P0（阶段 0-3）与 P1（阶段 4-5）完成，P2（阶段 6）完成一半。

**企业生产准入：不具备。** 四条阻塞线，其中两条是**范围性**的——不是「再多跑几次测试」能解决的：

| # | 阻塞线 | 性质 | 关键证据 |
| --- | --- | --- | --- |
| 1 | 真实环境验证未闭环 | 验证缺口 | `xws.sku.collection` 与 `huitun.keyword-heat.collect` 的发布段从未对真实目标执行过 `--commit`；`sycm.search-rank.export` 从未被真实浏览器驱动（§9） |
| 2 | 平台范围项未实现 | 范围缺口 | 控制平面、Browser Broker、多租户隔离、Object Storage、多 Agent 并发均未落地（README §2 已把它们列为当前非目标） |
| 3 | 工程与运维面缺失 | 交付缺口 | 无部署清单与环境 bootstrap、无监控告警、无 RPO/RTO 与恢复演练；CI 只覆盖离线层（L0-L2），真实浏览器/飞书/生产库明确不进 CI |
| 4 | 治理与决策未定 | 决策缺口 | README §11 九项待决策（部署区域、凭据托管、数据留存与 PII、SLA/RPO/RTO、并发规模、合规边界、模型供应商与预算、Temporal 去留）**全部未定** |

一句话：**它能跑，但还不能被交给一个不在现场的人，在无人值守的条件下，承担对外承诺。**

## 1. 先界定「投入企业生产」指什么

不界定就一定会吵架。按 README 的定位，至少要分开两个档：

| 档位 | 含义 | 当前状态 |
| --- | --- | --- |
| A. 受控内用 | 单机、单租户、人工在环（登录态、人工闸门、发布授权）、周更节奏 | **已经在跑**，且多数能力有真实回执（§5.1、PHASE-ARCHIVE §8） |
| B. 生产级交付 | 无人值守、多店铺/多账号并发、对外 SLA、可交接运维 | **不可**，README §2 把「长期无人值守运行」「十几或几十家店铺的生产级并发」明确列为非目标 |

现在具备的是 A，不是 B。下面的阻塞项都是针对 B 的。

**如果目标不是 B 档全部能力，而是「单机单店铺 + 客户自助操作」**（客户侧装在自己电脑上、非技术人员独立使用），
所需改造与优先级另见 [`docs/ops/CLIENT-DESKTOP-DELIVERY-PLAN.md`](../ops/CLIENT-DESKTOP-DELIVERY-PLAN.md)——
它复用本文件的结论，但把口径换成「客户能不能自己用」，并给出登录体检、扫码登录、飞书提醒与傻瓜修复的分档方案。

## 2. 阻塞项逐条

### 2.1 真实环境验证未闭环（验证缺口）

设计上「发布段必须回读验收」是对的，但**只有一部分能力在真实目标上兑现过这个承诺**：

- 已真实跑通并验收：`xws.feishu.import`（游标 1→3）、`sycm.feishu.weekly`（`rows=300 / historyRows=2367`、游标 1→300）。
- 从未对真实目标 `--commit`：`xws.sku.collection`、`huitun.keyword-heat.collect`。
- 端到端测试用的是**真 registry/loader/adapter/证据库/Controller，只有 store 在内存、飞书客户端是注入的假实现**——
  这能证明幂等与接线，不能证明真实平台的字段合同与限流行为。
- `sycm.search-rank.export` 从未被真实浏览器驱动（需要 Edge 调试实例上的生意参谋登录态）。

关闭动作：各补一次**同类演练**（在应用自持沙盒 base 里建一次性演练表、跑完即删），
照 `sycm.feishu.weekly`（§13.6）与 `xws.feishu.import`（MIGRATION-8 §8）的成例做。

### 2.2 平台范围项未实现（范围缺口）

- **控制平面**缺位：租户/店铺/账号/能力/权限/配额/人工任务，目前由配置与脚本约定承担。
- **Browser Broker** 缺位：现在依赖「本机已登录 Edge + 共享 CDP Proxy + 单浏览器级连接」，
  租约与互斥由运行时 lane 闸门近似实现，**没有** profile/account/tab 生命周期的所有权登记与孤儿清理。
  这也是「同一账号/profile 并发恒 1」只能靠约定维持的原因之一。
- **多租户隔离**：已做的是**单点配置 + 两套租户并存**（`feishu-targets.mjs` 切换 profile，见 TENANT-MIGRATION-MAP），
  不是架构意义上的租户隔离（配额、审计边界、数据隔离）。
- **Object Storage**：README §5 明写「当前仓库尚未实现此层」；大工件目前落在本地目录与证据目录里。
- **多 Agent 并发**：未开始（§12.1 阶段 6）。现在完成的是 Agent **分权**（Agent 只出 proposal + 四条降级出口 + 五条边界）。
- **Temporal 去留无书面结论**：POC 仍留在 `agent-runtime/temporal/`，默认由 PostgreSQL 承担（§12.4 第 4 条）。

关闭动作：取决于是否真要 B 档。要 B 档，Browser Broker 与多租户隔离必须先做（它们决定并发上限与隔离边界）；
不要 B 档，应在文档里把 2.2 整体标注为「非目标」，而不是留成模糊的待办。

### 2.3 工程与运维面缺失（交付缺口）

仓库自己的 `docs/standards/README.md` §8 已经写明：**不能承诺干净环境一键复现、完整 CI、生产级恢复**。
具体缺：

- 无部署清单、无环境 bootstrap、无 rollback/补偿方案（standards §12 要求「部署前必须有目标环境、凭据来源、回滚方案」）。
- 无 lint / build 定义；Python 侧曾有未声明依赖（`openpyxl`/`Pillow`/`python-docx`）与仓库外模块 `table_geometry`。
- 无监控、无告警、无失败通知渠道（README §11 把「失败通知渠道」列为待决策）。
- 无 RPO/RTO 与备份恢复演练。数据库侧目前只有**迁移前 backup**（如 `db/backups/pre-006-20260914-225707.sql`），
  是变更保护，不是恢复能力。
- CI 现状：`.github/workflows/ci.yml` 只跑 L0 语法 / L1 离线 self-test / L2 单测，按 skill 分矩阵；
  真实浏览器、飞书、生产 PostgreSQL **按设计不进 CI**（注释写明：集成测试由外部系统把关）。

关闭动作：补一份「运行基线」（部署清单 + 环境 bootstrap + 凭据注入方式 + 备份恢复步骤 + 最小告警面），
并把「变更前 backup」升级为「定期备份 + 至少一次真实恢复演练」。

### 2.4 治理与决策未定（决策缺口）

README §11 九项全部未定，其中四项直接决定能不能承诺生产：

- 目标 SLA、RPO/RTO、人工响应窗口与失败通知渠道。
- 部署区域、凭据托管、数据留存、PII 与删除要求。
- 第一阶段及目标阶段的店铺/账号/任务/并发规模。
- 各平台 API 与浏览器的合规边界（决定自动化是否合规可持续）。

README §11 的原文口径也是本文件的立场：**在这些决策明确前，不承诺生产级无人值守规模、上线日期或长期平台兼容性。**

## 3. 对照 README §10 的 11 条架构验收

「离线层证明」＝ 单元/夹具/故障注入能证明；「真实层证明」＝ 在真实浏览器/飞书/生产库上兑现过。
两者都要才算完整闭环。

| # | 验收条件 | 离线层 | 真实层 | 依据 |
| --- | --- | --- | --- | --- |
| 1 | Worker 被杀后可恢复且不重复提交副作用 | **已证** | 部分 | `recovery-fault-injection.mjs` 跨进程 SIGKILL→回收过期 lease→从游标 10 续跑到 20；重复 commit_key 不产生第二行（17/17） |
| 2 | 浏览器断开/插件停滞不把页面进度当完成 | **已证** | **已证** | 真实 1-40 页长跑在第 20 页 `STALLED` 被安全阻断，回执 `NOT_COMPLETED_ON_REAL_PLUGIN_RUN`；PG 权威 `completed_end=0` |
| 3 | partial artifact 不推进错误游标 | **已证** | 部分 | 连续前缀验证；迟到工件判 `REJECTED_FOR_CURRENT_ATTEMPT` |
| 4 | retry budget 耗尽后进入明确终态 | **已证** | 未证 | `task-queue.mjs` 退避/超时清扫 + supervisor 相关测试；未做真实长跑耗尽演练 |
| 5 | 同账号/profile/写目标不并发双写 | **已证** | 未证 | lane 闸门（写恒 1）+ lease CAS；真实多店铺并行未测 |
| 6 | 失败与人工路径释放资源并保留可恢复状态 | **已证** | **已证** | 人工闸门 + `PAUSED`；§13.7 的 `reclaimStale` / `assessRun`；真实两次人工释放（`controller.cancel`）后恢复正常 |
| 7 | Feishu 不可用时已验证源工件不需重新采集 | 设计成立 | 未证 | 证据库与发布阶段解耦；未做真实飞书故障演练 |
| 8 | 两店铺并行不串账号/数据/tab | 未证 | 未证 | 多店铺并发未开始（§2.2） |
| 9 | Adapter 版本变化不改工作流/权限/提交逻辑 | **已证** | 部分 | manifest/registry/适配器边界；`build-skill-registry --check` + `registryDigest` 校验 |
| 10 | 移除 Agent 后确定性链路仍可运行 | **已证** | 未证 | `assertAgentRemovable` + 无 Agent 路径；真实长跑下未单独验证 |
| 11 | 每个发布字段可追溯到 snapshot/evidence/commit | **已证** | **已证** | 证据链 + 真实回读收据（`rows=300 / historyRows=2367`、`verdict=VERIFIED`） |

合计：11 条里 **6 条完整闭环、4 条只到离线层、1 条（第 8 条）完全未证**。
「完全未证」的那条正好对应 §2.2 的范围缺口——所以架构验收清单自身也指向同一个结论。

## 4. 通往生产的最小路径（建议顺序）

1. **冻结运行基线**（不需要新功能）：部署清单 + 环境 bootstrap + 凭据注入 + 定期备份与一次真实恢复演练 + 最小告警面。
2. **补齐 3 条能力的真实发布段**（§2.1），把「回读验收」从设计承诺变成实测事实。
3. **决定要不要 B 档**：要，则先做 Browser Broker 与租户隔离（它们决定并发与隔离边界）；
   不要，则把 §2.2 明确标注为非目标，并据此收敛 README §11 的待决策项（SLA、并发规模、合规边界可以先给保守值）。
4. 上述完成后，再谈无人值守与对外承诺。

第 1、2 步是**工程工作**，不需要新架构决策，可以先做；第 3 步是**所有者的决策**。

## 5. 本文件不承诺什么

- 不承诺上线日期、生产级无人值守规模或长期平台兼容性（沿用 README §11 的口径）。
- 不把「测试通过」当作「已获授权」：commit/push/部署/真实外部写入各自仍需明确授权（standards §12）。
- 不把「离线层已证」表述成「真实环境已证」（本文件第 3 节刻意分列两栏）。
