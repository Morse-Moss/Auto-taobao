# 运营日报采集 SOP

## 1. 启动独立浏览器

```powershell
node runtime/start-daily-report-browser.mjs
node runtime/start-daily-report-proxy.mjs
```

确认 `9223` 和 `3458` 正在监听，且代理 `/health` 返回 `browser.id=edge-daily-report`。每次动作前从 `/targets` 重新发现页面，不保存 target id。

## 2. 店铺数据

在已登录的生意参谋中按以下路径操作：

```text
自助分析 -> 分析空间 -> 公共空间 -> 取数报表 -> 日报 -> 预览 -> 下载报表
```

已验证报表 id：`4300764`。下载后的工作簿应只有 `data` sheet，表头 119 列。选择请求日期对应的唯一一行；不要默认第一行永远是昨日。

## 3. 推广数据

进入 `https://one.alimama.com/index.html`：

1. 关闭直达计划或新建计划弹窗。
2. 打开 `报表 -> 营销场景报表`。
3. 营销场景同时选择 `关键词推广` 和 `人群推广`。
4. 转化统计周期选择 `30天累计数据`。
5. 数据汇总周期选择 `昨日`，汇总粒度选择 `分日`。
6. 确认后滚动到报表底部，点击 `下载报表 -> 确定`。
7. 打开 `下载任务管理`，等待任务显示 `生成成功`。
8. 下载 CSV 营销场景报表。最后一次下载按钮需要 CDP 真实鼠标事件；脚本触发的 DOM `.click()` 不会启动下载。

成功文件应是含一个 GB18030 CSV 的 ZIP。CSV 必须是 71 列、两条数据：场景 `371 / 关键词推广` 和 `372 / 人群推广`。

## 4. 询单量补充

在同一独立生意参谋浏览器中操作：

```text
服务 -> 店铺绩效 -> 业绩分析 -> 询单到付款 -> 日 -> 选择目标日期
```

页面表格中，以列名和行名交叉定位：

- `询单量` = `当日询单人数` 列的目标日期行。
- `同层同行询单量` = `当日询单人数` 列的 `同行同层均值` 行。

不要使用操作截图中的示例数字，也不要误取 `询单人数`、`同行同层优秀`、`汇总值` 或 `全店平均值`。先运行 `run-inquiry-backfill.mjs --date YYYY-MM-DD --source-shop 生意参谋店铺名 --shop 飞书店铺名` 生成干跑计划；脚本会先校验页头店铺身份。确认目标记录唯一且两个字段为空后，追加 `--commit`。脚本只更新 `询单量` 和 `同层同行询单量`，写后回读两项并验证其他字段未变化；相同来源值再次运行时应返回 `ALREADY_VERIFIED`。

## 5. 合并与回填

询单脚本拒绝多日期表格，以防把区间同行均值用于单日。提交前保存 `inquiry-attempt-*.json` 写前快照；写入响应异常只回读一次核实，不自动重发。若回读也失败，保留 `WRITE_OUTCOME_UNKNOWN`，下次执行前先用快照核对目标行和非询单字段。

先运行 Skill 入口脚本生成 dry-run `plan.json` 和 `paste.tsv`，核对请求日期、店铺名、目标 base/table、字段数和场景。API 有写权限时用同一命令追加 `--commit`。若 API 返回 `403 / 91403`，停止 API 重试，在飞书网格中新建一行、选中首列，通过代理 `POST /paste` 发送真实 `Ctrl+V`。随后用 `--verify-existing --expected-before-count N` 回读验收，其中 `N` 是粘贴前已确认的行数。

目标行顺序为：119 个店铺字段、69 个关键词推广字段、69 个人群推广字段。目标表前两列和末六列不在写入 payload 中。
